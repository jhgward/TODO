# 2026-09-28 FR-001(티켓 생성) 구현 사전 분석

기준: API_SPEC.md §1 `POST /api/tickets`, TEXT_CASES.md TC-API-001 (001-1 ~ 001-11)

## 요청 검증 (createTicketSchema, src/shared/validations/ticket.ts)
| 필드 | 규칙 | 에러 메시지 |
|------|------|-------------|
| title | 필수, trim 후 1~200자 | 누락·빈 값·공백만: "제목을 입력해주세요" / 초과: "제목은 200자 이내로 입력해주세요" |
| description | 선택, 최대 1000자, 기본 null | "설명은 1000자 이내로 입력해주세요" |
| priority | 선택, LOW/MEDIUM/HIGH, 기본 MEDIUM | "우선순위는 LOW, MEDIUM, HIGH 중 선택해주세요" |
| plannedStartDate | 선택, YYYY-MM-DD, 기본 null | (명세 없음) |
| dueDate | 선택, YYYY-MM-DD, 오늘 이후(Asia/Seoul), 기본 null | "종료예정일은 오늘 이후 날짜를 선택해주세요" |

## 처리 규칙
- status = BACKLOG 고정, startedAt/completedAt = null
- position = BACKLOG의 min(position) - 1024 (빈 칼럼이면 -1024, 명세 예시 기준)
- 응답 201 + 생성된 티켓 전체 / 실패 400 `{ error: { code: "VALIDATION_ERROR", message } }`

## 명세에 없는 부분 (구현 전 결정 필요)
1. dueDate가 "오늘"이면 허용인가
2. 빈 BACKLOG의 기준 position (예시상 0 → -1024로 추정)
3. title을 trim해서 저장하는가
4. plannedStartDate > dueDate 허용 여부, 날짜 형식 오류 메시지
5. 검증 에러가 여러 개일 때 어떤 메시지를 반환하는가

## 환경 관련 주의
- `.env.example`/`drizzle.config.ts`가 `DATABASE_URL` + 로컬 PostgreSQL로 바뀌었으나, TRD의 `drizzle-orm/vercel-postgres` + `@vercel/postgres`는 Neon 전용이라 로컬 DB에 붙지 않는다. `pg` 또는 `postgres` 드라이버 필요.
