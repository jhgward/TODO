## User Input

```text
$ARGUMENTS
```

위 입력이 이번 기록의 **요약**이다. 비어 있으면 변경 내용을 보고 한 줄 요약을 직접 만든다.

## 목적

코드를 수정하고 git에 반영하기 직전에, "어떤 요청으로 무엇이 바뀌었는지"를 남긴다.

- `CHANGELOG.md` (저장소 루트): 상세 이력. 새 항목을 맨 위에 쌓는다.
- `CLAUDE.md`의 `## 최근 변경사항`: 최근 14일의 한 줄 요약만 유지한다.

이 skill은 **기록만** 한다. 소스 코드를 고치지 않고, `git add` / `commit` / `push`를 하지 않는다
(사용자가 같은 메시지에서 커밋까지 요청한 경우에만 기록 후 커밋한다).

## 절차

### 1. 변경 내역 수집

저장소 루트에서 실행한다.

```bash
bash .claude/skills/changelog/scripts/collect-changes.sh
```

출력의 `BRANCH`, `DATETIME`, `SOURCE`, 파일 목록(`상태<TAB>추가<TAB>삭제<TAB>경로`)을 그대로 쓴다.
브랜치명·시각·라인 수는 **스크립트 출력만 사용**하고 추측하거나 직접 세지 않는다.

- `SOURCE=working-tree`: HEAD 대비 미커밋 변경 (새 파일 포함)
- `SOURCE=last-commit`: 작업 트리가 깨끗해서 마지막 커밋의 변경을 기록
- `SOURCE=none` 또는 `FILES=0`: 기록할 변경이 없다. 파일을 고치지 말고 사용자에게 알리고 끝낸다.

### 2. 프롬프트 모으기

이번 대화에서 **직전 `/changelog` 실행 이후**(없으면 대화 시작부터) 사용자가 입력한 요청을 순서대로 모은다.

- 사용자가 쓴 문장을 **그대로** 인용한다. 고쳐 쓰거나 요약하지 않는다.
- `/changelog` 명령 자체, "응", "진행해" 같은 확인 답변은 제외한다.
- 한 요청이 15줄을 넘으면 앞 10줄만 적고 `…(이하 생략)`을 붙인다.
- 비밀번호, 토큰, DB 연결 문자열 같은 비밀 값이 들어 있으면 그 부분을 `***`로 가린다.
- 이번 대화에 해당 요청이 없으면(새 세션에서 바로 실행한 경우) `> (이 세션에 기록된 프롬프트 없음)`이라고 적는다.
  지난 대화의 요청을 기억에 의존해 지어내지 않는다.

### 3. 변경 내용 분류

파일 목록과 실제 diff(`git diff HEAD -- <경로>`, 새 파일은 내용 확인)를 보고 **무엇이 바뀌었는지** 한 줄씩 적는다.

- **Added**: 새 기능·새 파일 (상태 `A`)
- **Modified**: 기존 동작·내용 수정 (상태 `M`)
- **Deleted**: 삭제 (상태 `D`)

관련 파일이 여러 개인 변경은 한 줄로 묶고 파일 경로를 모두 적는다. 파일명만 나열하지 말고 변경의 의미를 적는다.

### 4. 테스트 결과

**이번 대화에서 실제로 실행한** 테스트·검사 결과가 있을 때만 `### Tests`에 적는다 (명령어, 통과/실패 수).
가장 최근 실행 결과를 쓴다. 실행한 적이 없으면 `### Tests` 섹션 자체를 넣지 않는다.
기록을 위해 테스트를 새로 돌리지 않으며, 실행하지 않은 결과를 적지 않는다.

### 5. CHANGELOG.md에 항목 추가

파일이 없으면 아래 머리말로 만든다.

```markdown
# Changelog

`/changelog "요약"`으로 기록하는 변경 이력. 최신 항목이 위에 온다.
```

새 항목을 머리말 바로 아래(기존 항목들의 **위**)에 넣는다. 기존 항목은 수정하거나 지우지 않는다.

```markdown
## [브랜치명] - YYYY-MM-DD HH:MM

**Summary**: 요약

### Prompt
> "사용자가 입력한 요청"

### Changes
- **Added**: 새 기능 (`파일경로`)
- **Modified**: 수정 내용 (`파일경로`)
- **Deleted**: 삭제 내용 (`파일경로`)

### Files Modified
- `파일명` (+10, -2 lines)

### Tests
- `npm run test` — 124 passed, 0 failed
```

작성 규칙:

- 프롬프트가 여러 개면 `> "…"` 블록을 요청마다 하나씩, 빈 줄로 구분해 적는다. 여러 줄 요청은 줄마다 `> `를 붙인다.
- `Changes`에서 해당 없는 분류(Added/Modified/Deleted)는 줄을 넣지 않는다.
- `Files Modified`는 스크립트 출력 순서대로, 추가·삭제 라인 수는 출력 값 그대로 적는다.
  - 새 파일: `(+N lines, new)` / 삭제된 파일: `(-N lines, deleted)` / 바이너리(`-`): `(binary)`
  - 한 디렉터리의 새 파일이 10개를 넘으면 `` `디렉터리/` (새 파일 N개, +합계 lines) `` 한 줄로 묶는다.
- `SOURCE=last-commit`이면 `**Summary**` 아래에 `**Commit**: <HEAD 해시>` 줄을 추가한다.

### 6. CLAUDE.md의 최근 변경사항 갱신

`CLAUDE.md`에서 아래 두 마커 **사이만** 고친다. 마커 밖의 내용은 건드리지 않는다.

```markdown
## 최근 변경사항

<!-- changelog:recent:start -->
- 09-30 18:12 [main] 요약 (파일 12개)
<!-- changelog:recent:end -->
```

- 새 줄을 맨 위에 추가한다: `- MM-DD HH:MM [브랜치] 요약 (파일 N개)`
- 기록 날짜가 오늘 기준 **14일을 넘은 줄은 삭제**한다 (CHANGELOG.md에는 그대로 남는다).
- 섹션이나 마커가 없으면 `CLAUDE.md` 맨 끝에 위 형태로 새로 만든다.

### 7. 보고

사용자에게 짧게 알린다: 기록한 항목의 제목(브랜치·시각), 요약, 파일 수, 테스트 결과 포함 여부,
그리고 `CHANGELOG.md`와 `CLAUDE.md`도 커밋에 포함해야 한다는 점.

## 실행 시점

**커밋하기 전에** 실행하면 `CHANGELOG.md`와 `CLAUDE.md` 변경이 같은 커밋에 들어간다.
커밋한 뒤에 실행하면 마지막 커밋 기준으로 기록되고, 두 파일은 별도로 커밋해야 한다.
